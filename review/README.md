# Repetitionssystem

`review/` lagrar betydelsefulla kunskapsluckor som bör återkallas eller tillämpas igen efter distans. Syftet är diagnostik och långsiktig förståelse, inte betygsättning.

## Vad som loggas

Ett repetitionsobjekt skapas när ett svar eller en implementation visar:

- en felaktig mental modell,
- en viktig precisionslucka,
- något som inte kunde återkallas,
- eller ett glapp mellan teoretisk förståelse och praktisk tillämpning.

Små felskrivningar och isolerade misstag utan framtida lärvärde loggas inte. Relaterade fel grupperas under samma objekt, och ett återkommande problem läggs till i objektets historik i stället för att skapa en dublett.

## Arbetsflöde

1. Svaret eller implementationen granskas och rätt modell förklaras.
2. Ingen omedelbar omskrivning krävs enbart för att upprepa korrigeringen.
3. En betydelsefull lucka registreras som ett repetitionsobjekt.
4. Arbetet fortsätter enligt den aktuella enheten.
5. Objektet återkallas efter ett meningsfullt uppehåll, när konceptet används naturligt eller under fasens konsolidering.

Korrekt tillämpning i projekt- eller labbkod räknas som starkare evidens än att endast återge en definition.

## Statusar

- **Öppen:** Konceptet har ännu inte återkallats korrekt efter den ursprungliga korrigeringen.
- **Förstärkt:** Konceptet har återkallats eller tillämpats korrekt en gång efter distans.
- **Stabil:** Konceptet har demonstrerats korrekt vid minst två separerade tillfällen, varav minst ett genom tillämpning när det är möjligt.

Status kan flyttas tillbaka om samma missförstånd återkommer.

## Statistik

Varje fasfil sammanfattar antal förutsägelsefrågor, första resultat och repetitionsobjekt per status. Klassificeringarna är diagnostiska och kan innehålla bedömning. De ska inte behandlas som poäng eller mål att optimera.

## Ägarskap

Codex underhåller normalt repetitionsloggen utifrån observerade svar och implementationer. Adam kan korrigera klassificering eller innehåll när loggen inte speglar hans förståelse.
